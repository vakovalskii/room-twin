# Room Twin — цифровой двойник комнаты

`телефон (capture.html: кадры + гироскоп) → room-capture.json → scripts/build_room.py → room.json + room.html`

Телефон только собирает данные: встаёшь в центр комнаты и поворачиваешься, страница сама снимает
кадр каждые 15° и пишет направление камеры. Всё тяжёлое считает этот скилл на компьютере.

## Предпосылки (проверь, при отсутствии доведи пользователя)
1. Python 3.10+ и `uv` (или `pip install -r requirements.txt`).
2. Модель глубины `models/da2-metric-indoor-small.onnx` (99 МБ). Если её нет — один раз
   сконвертировать официальную (нужен интернет, ставит torch во временное окружение):
   ```bash
   uv run --python 3.12 --with torch --with transformers --with onnx --with onnxruntime \
     python tools/export_depth.py models/da2-metric-indoor-small.onnx
   ```
3. Ключ NeuralDeep Hub с доступом к vision-модели: `export NEURALDEEP_API_KEY=sk-...`
   (без него скрипт ищет ключ провайдера `neuraldeep` в `~/.config/opencode/opencode.json`).
   Получить: https://hub.neuraldeep.ru → кошелёк или подписка → Ключи.

## Шаг 1. Съёмка
Страница `web/capture.html` нужна телефону по **https** (иначе Safari не даст камеру и гироскоп).
Проще всего — с компьютера в той же Wi-Fi:
```bash
python scripts/serve_capture.py          # печатает https://<ip>:8443/capture.html
```
На iPhone открыть ссылку, принять самоподписанный сертификат («Подробнее» → «Перейти»),
разрешить камеру и «Движение и ориентация». Инструкция для человека — на самой странице:
центр комнаты, телефон вертикально, медленный круг, по желанию второй круг с наклоном вниз.
По «Готово» скан уходит на компьютер в `captures/`. Если страница открыта не с этого сервера,
она отдаёт файл `room-capture-*.json` через «Поделиться» — его надо передать на компьютер.

## Шаг 2. Сборка
```bash
uv run --with numpy --with onnxruntime --with pillow \
  python scripts/build_room.py captures/room-capture-....json --out out/<комната>
# → out/<комната>/room.html  (открыть в браузере), room.json, frames/
```
Флаги: `--hfov 69` (угол обзора камеры по длинной стороне кадра; iPhone 1x ≈ 69, 0.5x ≈ 108),
`--cam-height 1.4` (высота телефона над полом, м), `--no-vlm` (только стены, без предметов).
Env: `NDT_VISION_MODEL` (деф. `qwen3.6-fp8-noreason`), `ANALYZE_WORKERS` (деф. 4), `ND_BASE_URL`.

## Что отдать пользователю
- `room.html` — 3D-вьюер (перспектива/сверху, подписи стен W01–W04 и проёмов P01, размеры,
  клик по «Свет» включает светильники, список предметов). Открывается двойным кликом.
- Размер комнаты и `fit_error_m` из вывода: если разброс стен > 0.3 м, сказать, что скан шумный
  (человек ходил, а не вращался на месте, или мало кадров) и предложить переснять.
- Список предметов из `room.json` — для проверки глазами: VLM ошибается на тёмной мебели.

## Правка
`room.json` — источник правды. Поправить размер, предмет или стену можно прямо в нём и
пересобрать HTML без повторной разметки:
`python scripts/render_html.py out/<комната>/room.json`.

## Границы
- Точность — десятки сантиметров: глубина из одной камеры, а не LiDAR. Высоту потолка лучше
  ввести на странице съёмки (по умолчанию 2.7 м).
- Комната считается прямоугольной. Г-образные и скошенные стены сведутся к прямоугольнику.
- Скан из центра одной точки: за большим шкафом или диваном не видно, что там.
- Разметка — это десятки vision-запросов (кадр ≈ 20 с, по 4 параллельно): учитывай кошелёк Hub.
